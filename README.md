# Commerce Suite

多商户全渠道电商系统。买家可以把不同店铺的商品一起结算，商家分别履约，财务按店铺核对销售、佣金、退款冲正与结算批次。

## 功能

| 业务 | 已实现 |
| --- | --- |
| 平台运营 | 入驻审核、收款主体及协议留痕、自营店铺、暂停及恢复接单、操作审计 |
| 商户工作台 | 店主配置商品、配送、门店核销、售后和财务岗位，各店独立查账 |
| 商品目录 | 分类与系列、独立规格 SKU、商品版本审核、按渠道发布、下架及分类和规格搜索 |
| 会员营销 | SKU 会员价、跨店固定及比例优惠、阶梯规则扩展、分类限定、单次券、活动版本、叠加与分摊 |
| 购物车 | 多设备共用、按行勾选结算、十分钟报价快照 |
| 配送计费 | 店铺按仓或按单计费、券后满额包邮、运费版本留痕、可安装计费扩展 |
| 库存与预售 | 店铺多仓、按仓预占与扣减、预售批次和额度、超时释放、到货入库 |
| 订单支付 | 母子单、支付意图、渠道扩展、签名回执、渠道流水去重、迟到及重复实收处置 |
| 商家订单 | 按本店与 UTC 下单日期查询配送和自提订单，查看金额、运费和履约状态，支持游标翻页 |
| 履约 | 分仓发货、同仓拆包、运单查询和签收回放、门店备货及一次性提货码 |
| 售后 | 按订单行申请退货、登记寄回运单、收货质检、指定仓回库、签收退款回执、冲正货款和佣金 |
| 积分 | 版本化赚取和抵扣规则、结账预占、按原规则处理部分退款、账户明细与平台出资结算 |
| 结算 | 按店和月份预览应结、冻结明细、财务复核、出纳登记银行流水、商家导出本店账单 |
| 渠道对账 | 导入本地渠道 CSV，逐笔核对收款、退货退款和异常实收退回，保留差异与回执链接 |
| 财务 | 销售与退款分录、佣金、未结余额、按店铺生成结算批次及负余额结转 |

## 本机运行

需要 64 位 PHP 8.2 或以上和 `pdo_mysql`。新部署使用 MySQL 8.4 LTS，现有 MySQL 8.0.16 或更高补丁版的 8.0 部署仍可运行。本项目无需安装 Composer 依赖。先创建空库 `commerce_suite` 和有该库权限的专用账号。

```sh
export COMMERCE_DSN='mysql:host=127.0.0.1;port=3306;dbname=commerce_suite;charset=utf8mb4'
export COMMERCE_DB_USER='commerce'
export COMMERCE_DB_PASSWORD='<本地数据库密码>'
export APP_DEMO=1

php bin/commerce.php migrate
php bin/commerce.php health
php bin/commerce.php seed
php -S 127.0.0.1:8080 -t public
```

PowerShell 使用 `$env:变量名 = '值'` 设置环境变量。Windows 如未加载 PDO MySQL，请在 `php.ini` 启用 `extension=pdo_mysql`。打开 [本机商城](http://127.0.0.1:8080/)。

## Docker Compose

复制 [配置样例](.env.example) 为 `.env`，填写两个不同的 MySQL 密码。体验演示时设置 `APP_DEMO=1`，再运行以下命令。Compose 默认仅将 Web 端口绑定至本机，数据库迁移成功后启动 Web 和后台任务。

```sh
docker compose up -d --build --wait
docker compose exec app php bin/commerce.php seed
```

打开 [本机商城](http://127.0.0.1:8080/)。已有 MySQL 8.0 数据卷时，先在 `.env` 中指定 `COMMERCE_MYSQL_IMAGE=mysql:8.0`。日常维护及跨版本迁移参见[部署与恢复](docs/deployment.md)。

## 演示

演示密码统一为 `CommerceDemo-2026`。演示种子要求空用户表和 `APP_DEMO=1`，应用也通过这一变量控制模拟支付入口。

| 角色 | 邮箱 |
| --- | --- |
| 买家 | `buyer@example.test` |
| 商家 A | `north@example.test` |
| 商家 B | `pond@example.test` |
| 平台运营 | `admin@example.test` |
| 财务 | `finance@example.test` |
| 出纳 | `payout@example.test` |

1. 买家在商城点「领券」，添加山形帆布托特包（¥120）和湖蓝陶瓷早餐杯（¥80）。购物车选门店自提，为两家商户各选一个提货门店。选中已领的跨店券并计算费用，应付 ¥180。
2. 提交报价并模拟支付。在两家商户的门店自提工作台分别标记备货完成。买家在两个子订单分别生成提货码，店员输入码或通过 Code 39 扫描枪核销，子订单金额是 ¥108 和 ¥72。
3. 买家给托特包申请退货。商家 A 同意退货并填写寄回地址，买家登记运单，商家验收 1 件，按商品状态填写可售回库件数。按下方指令确认退款 ¥108，同时冲正 ¥10.80 佣金。
4. 财务分别打开两家店的结算预览并冻结当期明细。商家 A 应结 ¥0，商家 B 应结 ¥64.80。复核两张单据后，B 店进入待打款。

店主可绑定自提门店与库存仓，为门店创建专属核销账号。扫描枪使用键盘输入模式，对准买家订单页条码，将 16 位码输入到该子订单的核销表单。

### 回放沙箱支付

为本地应用和回放终端设置同一个至少 32 字节的 `COMMERCE_SANDBOX_WEBHOOK_SECRET`，并设置 `APP_DEMO=1`。在待付款订单页复制沙箱支付意图，以分为单位回放收款。以下示例对应应付 ¥180 的订单。

```sh
php bin/sandbox-payment.php 8080 '<支付意图>' example-receipt-001 18000
```

重复执行同一条命令三次，回执编号和支付编号保持一致。可在运营台查看回执以及待核对的金额或币种差异；财务可登记迟到或重复实收的模拟退款回执。接口签名和返回格式见[架构与业务规则](docs/architecture.md#沙箱支付回执)。

自托管可按[支付渠道接入说明](docs/payment-channels.md)配置外部收银台和已验签的渠道回执。启用渠道时，订单固定使用下单时的渠道，账单可通过 `provider` 列区分不同渠道的同号流水。

### 回放退货退款

为本地应用和回放终端设置同一个至少 32 字节的 `COMMERCE_SANDBOX_REFUND_SECRET`，并设置 `APP_DEMO=1`。以财务账号打开「退货退款回执」，复制待退款记录的沙箱意图与原支付流水，再以分为单位回放。

```sh
php bin/sandbox-return.php 8080 '<退款意图>' example-return-001 '<原支付流水>' 10800
```

验收后按原订单行商品实付计算退款。需要退原配送费时，商家客服或平台财务在退货审核通过后、验收前登记金额和处理依据。登记方承担费用，每张子订单的累计退运费以原配送费为限。回执金额须等于货款和已批准运费之和。回执入账后，买家可查退款流水，财务可查退款和佣金冲正分录。已结算订单的退款进入后续结算批次。

运营发布领券活动时可开启「全单退完返还未过期优惠券」。母订单的所有商品都收到退款确认后，原券恢复到买家账号，保留原折扣、门槛和截止时间。停用期间无法使用，已过期券继续保留使用记录。买家可从原订单查看返券时间。

跨店活动也可按金额比例优惠并设定上限。运营可在「会员与营销」选择优惠方式。[营销规则与阶梯扩展](docs/promotions.md)

### 启用会员积分

1. 在「平台运营 → 会员与营销」发布积分规则。演示可设每元赠 2 积分、商品金额最高抵扣 20%，勾选退款时返还抵扣积分。赠送与抵扣比例都设为 0 可暂停新交易使用积分。
2. 买家先购买 ¥120 商品并付款，账号获得 240 积分。再次购买同一商品时填 100 积分，确认订单预占 100 积分，实际应付 ¥119。待付款取消或超时释放预占。
3. 完成履约并全退这件商品。沙箱退款回执为 11900 分，确认后返还 100 抵扣积分，扣回本单赠送的 238 积分。订单和积分明细可查原版本和两条变动。

1 积分抵 1 分，抵扣范围为券后商品金额。赠送积分按商品行的现金实付向下取整，运费不计入。赠分已花完时，退款扣回仍记入余额，后续获赠积分抵消欠额。

### 核对月结与打款

1. 财务在平台运营页点击该店的「结算预览」，核对月份、销售、退款和净佣金。确认后冻结分录，在结算单上输入复核金额，单位为分。A 店填 `0` 后结清，B 店填 `6480` 后进入待打款。
2. 在演示环境，用出纳账号打开 B 店结算单，输入测试流水号 `demo-bank-001` 和金额 `6480`，登记打款结果。自托管时，在银行端完成转账后录入对应流水。
3. B 店进入「本店账单」下载结算单 CSV。示例分录的 `gross_minor`、`commission_minor` 和 `net_minor` 分别为 `7200`、`720` 和 `6480`。按 `event` 和 `merchant_order_id` 可追到原始分录及子订单。

月份以 UTC 计算。每店每月只生成一张结算单，冻结后新增分录顺延到下一次关期。净额为负时继续结转，等后续销售抵扣后再冻结。首次运行演示时可对当前月关期。

退款分录的 `gross_minor` 是现金总额，包含实际退给买家的运费。`platform_freight_minor` 记录平台承担的运费，`platform_points_minor` 记录积分出资及其冲回。两列都计入商家应结净额。退运费不冲减佣金，平台出资的积分计入商品佣金基数。

### 导入渠道账单

1. 用沙箱回放产生收款或退款回执，在「渠道对账」下载 [CSV 模板](public/channel-bill-sample.csv)。将样例母单号和外部流水替换为本次回放的实际值，金额使用整数分。
2. 财务上传渠道账单后记下任务编号。商户店主和店铺财务也可从「本店账单」上传本店证据。
3. 运行 `php bin/commerce.php reconcile`，刷新任务页。财务可以打开匹配到的本地回执，查看同一流水的重复行、金额差异和待补回执。
4. 正式回执晚到时，从任务页重新排队待补行并再运行对账命令。重复上传同一份文件会返回原任务。同一份账单中的格式错误可修正后单独补交。

导入依赖已记录的渠道回执。订单、库存和账务继续由原支付与退款流程更新。

### 演示分仓配送

商家可以在商品与库存页新增仓库，再按仓调整某个 SKU 的库存。给默认仓留 1 件，另一个仓放 2 件，买家选择快递配送并下单购买 3 件。报价显示 2 个发货仓和 ¥16 运费。付款后分别在两个仓下登记包裹，使用不同的运单号。

为本地应用和回放终端设置同一个至少 32 字节的 `COMMERCE_SANDBOX_SHIPPING_SECRET`，并设置 `APP_DEMO=1`。如果承运商代码为 `demo`，两个运单号为 `WAYBILL-01` 和 `WAYBILL-02`，可回放以下签收。

```sh
php bin/sandbox-shipping.php 8080 demo WAYBILL-01 delivery-001
php bin/sandbox-shipping.php 8080 demo WAYBILL-02 delivery-002
```

买家在订单详情查看每件包裹的签收状态。商品全部发出且包裹全部签收后，子订单完成履约，商家账单新增一笔销售分录。回调字段见[沙箱签收回执](docs/architecture.md#沙箱签收回执)。

### 发布店铺运费规则

在「商家中心 → 运费规则」选择按发货仓计费或按本店订单固定计费，填写基础运费与可选包邮门槛。未配置时每个实际发货仓收取 ¥8.00。门槛按本店商品券后、积分抵扣前金额计算，门店自提免运费。发布后，尚未确认的旧报价须重新计算，已下单的运费和版本可在店铺订单中查询。[运费扩展与示例](docs/freight.md)

### 演示预售批次

1. 商家在已上架 SKU 的「预售批次」中选择库存仓，填写额度、截单时间和预计到货日。自提批次需使用门店绑定的仓库。
2. 买家在商品页选购指定批次，按正常流程结账。下单占用该批额度，关单释放，付款后仍可在订单页查看预计到货日期。同一 SKU 在购物车里保留一个购买方式或批次。
3. 到货后，商家凭实收数量登记整批入库。先分配给预售订单，剩余数量转为现货。实收不足时，补足已付款和待付款的数量后再入库。
4. 配送单可先发已付款的现货，最后一个包裹签收后完成履约。含预售商品的自提单在全部商品到货后开放备货。

## 运维与验证

- 从 v0.1.0 升级时，先备份数据库，停止应用写入，再运行 `php bin/commerce.php migrate` 并重启应用。升级保留原有订单、分录和账号，将既有商户账号设为本店店主。旧版未登记收款主体及协议的记录保留为未登记，待审店铺可由店主补交。仍有效的旧买家会话会在首次访问时合并购物车，旧购物车报价需重新计算。
- 已上架的旧商品保留原 SKU、价格、库存和配送及自提渠道；旧记录的分类和规格可由商户补录并提交平台审核。
- 升级时把旧 SKU 库存和预留量迁入各店默认仓。已经履约的旧订单沿用原运单号，待履约的配送订单可在默认仓登记包裹。
- 历史自提单保留原提货地址和核验记录。商家可在门店自提工作台继续办理待提货的历史订单，并补录旧门店资料后开放新单。还未下单的旧自提报价需重新选择门店。
- 旧版已审批并冲正的退款保留原金额、数量及分录，升级时保持原库存余额。原待审申请可继续审核、寄回和验收。
- 旧结算批次以「历史批次」保留并可导出。旧版未记录的结算月份、复核和银行流水保持为空。正常营业的旧店铺可由店主补录收款主体，核验通过后可冻结应结为正的新结算单。
- 迁移 0017 从母订单回填子订单下单时间，并建立店铺与下单时间索引。按维护窗口停写后执行迁移，恢复服务后可从商家中心查询旧单。
- Compose 自带后台任务。原生环境可在进程管理器下运行 `php bin/worker.php`，每轮释放至多 200 张超时订单、处理至多 100 条账单。也可单独手动运行 `php bin/commerce.php expire` 或 `php bin/commerce.php reconcile`。
- 创建自有运营账号时，通过环境变量 `COMMERCE_OPERATOR_PASSWORD` 传入密码，并运行 `php bin/commerce.php operator admin operator@example.com`。分别为运营、财务和出纳创建独立账号，角色为 `admin`、`finance`、`payout`。
- 在独立、库名以 `_test` 结尾的 MySQL 库设置 `APP_DEMO=1` 并执行迁移，然后运行 `php tests/integration.php`。并发库存用例需要 CLI 支持 `proc_open`。
- 启动带种子数据的本机演示后，可用 `python tests/web_smoke.py` 验证各角色通过网页完成交易。为应用和测试进程配置支付、签收、退款三个沙箱密钥即可覆盖签名回执。
- 支付、退款和签收回放使用独立演示数据库。外部服务接入现状见[支持范围](SUPPORT.md)。
