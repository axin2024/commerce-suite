# 企业采购演练

版本需求和可复验结果见[采购产品需求](requirements/08-企业采购-prd.md)及[验收记录](procurement-verification.md)。

从空库运行迁移并执行演示种子后，可以用四个账号完成这笔采购。各角色登录后从导航进入“企业采购”。采购单号与零售订单号分别编号，授信和预算以人民币分记账。

1. 平台运营登记法人编码、结算抬头和总部买家邮箱。以总部买家登录，创建门店并填写成本中心和收货地址，在签约商家中选择北仓选物。需要其他采购员时，在具体门店授权其已注册的买家邮箱。
2. 总部负责人打开门店，设置当月成本中心额度为 100000 分，超过 80000 分须复核。相同法人、月份及成本中心的门店共用预算。财务为该法人配置 100000 分授信。
3. 北仓商家选择签约企业和在售 SKU。首次发布基版号填 0，填写涵盖演练日期的有效期。在阶梯输入框逐行粘贴下方样例，然后发布。

   ```text
   1,99,0,1000
   100,1000000,0,900
   ```

4. 采购员进入门店，以 100 件试算，应看到每件 9 元、总价 900 元。新建询价，输入规格和数量（例如“帆布袋,100”），选择商家及未来的 UTC 截止时间。多家比价时，先分别完成各商家的授权和协议发布。
5. 商家在受邀询价中逐行选取 SKU，填写整单运费并提交。零运费时此单总价为 900 元。同一份投标内多行选中同一 SKU 时，系统将数量合计后取阶梯，并保存各行的协议版本及单价。
6. 截止后采购员打开门店，在报价明细核对规格、SKU、协议版本、运费和含运总额，选择收货门店及授标数量。系统只接受每家供应商在截止前的最后一版。迟到版仍可在历史中查询。
7. 900 元触发本例的总部复核。负责人在收货门店逐行批准，核减须填写理由。全部数量填 0 可驳回，已占预算同步释放。批准后生成采购单，账单抬头、配送地址和金额随单保存。法人或部门额度不足时页面给出原因。
8. 到货时从采购单选取原采购行，录入送货单号、实收和破损数量。100 件可分两批签收 60 和 40 件，每批保留回执。破损数量留待补货。相同送货单号和采购行重送相同数量，读回原回执。
9. 财务在法人名下关闭收货月份，下载账单。银行到账后上传[样例流水](../examples/procurement-bank.csv)，将 600 元和 300 元逐笔分摊到该单的未结行。每笔分摊都有核销编号，未分摊部分留作待核销余额，已分摊金额释放该单信用占用。
10. 演练跨期退货时，先仅收 60 件，关闭当月，再从该张收货单退回 10 件。下载收货单、原账单和贷项 CSV，按 `award_id,order_id,line_no,receipt_id` 对照。原账单货款 540 元，下一开放期间贷项为 −90 元。首次实收时整笔运费入账一次。本例采用零运费。

总部可为同一买家在不同门店分别授予采购或收货岗位。收货员通过送货单号录入框接收键盘式扫码枪输入，提交实收、破损和待补数量。采购工作台可按法人、门店及收货周查询；收藏的采购单和下载链接每次读取时重新检查授权。

## 账期与恢复

由财务或运营登记结算法人时选择 IANA 时区，收货和退货以该法人的当地月份归属账期。截止时间和收货周筛选使用 UTC。月内提前关账后，本月新业务记入下一个开放月。关账冻结原收货和贷项明细，后续核销在独立的流水分摊表记账。

在 v0.3.0 数据库的隔离副本运行下列命令，保存两次输出，核对零售订单、退款待办和归属异常。执行迁移前按[部署与恢复](deployment.md)备份数据库。七个新增迁移创建企业采购表，旧零售订单继续使用原编号；试点法人主动登记后授信从零开始。

```sh
php bin/commerce.php procurement-preflight > before.json
php bin/commerce.php migrate
php bin/commerce.php health
php bin/commerce.php procurement-preflight > after.json
```

退出试点时，财务点击“停收新询价”，存量询价继续投标、审批、履约和核销。预检 JSON 列出待审批编号、未收数量、未关账明细、未分摊来款和各法人最后授信分录。逐项处理后再导出。恢复时先在隔离库还原一致性快照，以相同请求号、送货单号和银行流水号回读，对照银行原始回执确认后再开放写入。CSV 证据可以从同一快照中的冻结行重新导出。

## 授标接口

向 `POST /procurement/awards` 提交 JSON。使用买家登录会话，`X-CSRF-Token` 使用该会话表单中的 CSRF 值，`Idempotency-Key` 填调用方生成的唯一业务键。部署时将此路径交给 PHP 前端控制器。以下整数应替换为当前门店工作台读到的编号。`bid_revision` 使用冻结报价的唯一编号，即页面显示的“报价 #”，每个供应商的版次另列。

```json
{"rfq_id":1,"bid_revision":3,"ship_to":2,"accepted_lines":[{"line":1,"qty":100}]}
```

成功返回 `award_id`、`status`、`order_id` 和 `credit_reserved_minor`。待复核时订单号为 null，信用占用为 0。相同请求重送可查询原授标及后续生成的订单。更换请求内容须更换幂等键；同一询价已有生效授标时须先处理原授标。授信不足或键冲突返回 409，门店对当前账号不可见返回 404，无效字段返回 422。
