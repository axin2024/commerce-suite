# 多商户全渠道电商系统 1.0 产品需求文档

**企业采购商城与账期结算**

需求评审版 · 2026-11-26 · 计划基线 v0.3.0（24ce943）

## 产品目标与交付边界

当前发行覆盖多商家零售订单、分仓履约与商户结算。本版支持以下业务流程。采购员为三个门店集中询价，总部审批后分批收货，月底按法人核销账款。 [现有项目说明](../../README.md) · [上一版业务需求](02-业务与交互-prd.md)

单价和运费只在授标前比较，企业赊销使用独立应收科目。外部银行流水通过 CSV 导入，测试用公开格式和合成流水。

## 使用者与工作台

采购经理提报，商家投标，总部预算负责人复核，收货员按门店验收，财务按法人核销。

采购工作台按法人、门店、收货周筛选。采购员从报价对比展开 SKU 阶梯、运费与含税总额，审批人看到预算和授信两份余额。收货扫码录入实收和破损，财务由账龄直接定位收货行。

## 功能需求

下列六项均纳入正式版本。验收编号按项目独立，后文列出每项的触发条件和预期结果。

| 需求 | 模块 | 产品行为与约束 | 验收 |
| --- | --- | --- | --- |
| R1 | 采购组织 | 总部建采购组织和成本中心，门店绑定收货地址，财务指定唯一结算主体。 | A1、A2 |
| R2 | 协议目录 | 商家按有效期发布合同目录，数量阶梯以同 SKU 合计，报价冻结单价与协议版。 | A3、A4 |
| R3 | 询报价 | 买家发询价单给选定商家，商家密封报价，采购员在截止后比较含运费总价并授标。 | A5、A6 |
| R4 | 采购审批 | 部门预算按月占用，超阈值转总部复核，驳回释放占用并允许改版。 | A7、A8 |
| R5 | 授信与履约 | 信用按法人共用，订单确认占用，按门店到货行验收并记录短收待补。 | A9、A10 |
| R6 | 月结与核销 | 财务按账期生成应收，按款项逐单核销，退货在下一开放账期形成贷项。 | A11、A12 |

## 页面操作与回执

| 关联需求 | 角色与入口 | 操作细节 | 需要读回的字段 |
| --- | --- | --- | --- |
| R1 · 采购组织 | 组织管理员/审批授权 | 关联子门店与结算法人，按组织路径审查可见订单 | buyer_org_id、billing_org_id |
| R2 · 协议目录 | 商家合同专员/协议价目 | 预览指定数量及日期的命中阶梯，发布合同版本 | agreement_rev、price_minor、valid_until |
| R3 · 询报价 | 采购员/报价对比 | 截止后选择中标行，采购审批通过才可转正式订单 | award_id、bid_revision、order_id |
| R4 · 采购审批 | 成本中心主管/预算待办 | 逐行批准数量，对驳回部分填写理由并释放占用 | decision_id、remaining_minor |
| R5 · 授信与履约 | 仓管/到货签收 | 选择原采购行录入实收、破损和待补数量 | receipt_id、accepted_qty、open_qty |
| R6 · 月结与核销 | 应收会计/法人对账 | 勾选未结应收分摊到账金额，余款作为待核销余额 | allocation_id、unapplied_minor |

演练用人民币分记账，协议价 900 分/件。授标仅锁定报价，订单生成须有有效预算批复及信用预留，两项之一失败即释放本次新增的预留。

## 状态、权限与数据

采购申请 草拟→待批→已占用→已下单→部分收货→收齐→结清。驳回回到可修订，短收保留未交行。

报价币种固定为合同币种，数量乘冻结单价后按行舍入到分。账期按法人时区、收货日归属，跨月退货引用原行。

MySQL 保存业务记录与操作回执。下列为新增逻辑对象和关键字段，所有归属组织的数据都须持有可校验的组织标识。

- `buyer_org(parent_id,billing_org)`
- `price_agreement(sku,tier,effective_at)`
- `credit_entry(org,order,delta)`
- `receipt_line(order_line,accepted_qty)`
- `statement_line(receipt_id,amount_minor)`

组织只在所属商家协议范围内检索，合同目录按买方和商家联合索引。 写入前校验操作者对目标对象的权限与当前修订。详情、搜索、导出和后台重试按同一归属校验。保留决定者、请求号、前后状态、发生时间及关联证据编号。

## 核心接口与集成

主要写入入口为 `POST /procurement/awards`。请求必填字段为 `rfq_id, bid_revision, ship_to, accepted_lines`。成功回执提供 award_id, order_id, credit_reserved_minor。请求另带租户身份和幂等键。相同键及相同内容返回原业务编号，相同键对应不同内容返回 409。输入不满足业务约束时返回 422 和字段路径，身份无权限读取的跨租户对象返回 404。

需要异步处理时，接收事务同时写入业务记录与待处理事件，再返回 202 及回执查询地址。回读须显示当前状态、已完成步骤、上次失败原因和可重试条件。外部系统已受理但应答丢失时，按原请求身份核查实际结果。

### 合成请求与业务回执样例

请求体示例使用演练环境中的对象。带摘要的样例在开发验收时应替换为实际文件或参数的计算值。

```json
{
  "rfq_id": "Q8",
  "bid_revision": 3,
  "ship_to": "STORE2",
  "accepted_lines": [
    {
      "line": 1,
      "qty": 100
    }
  ]
}
```

业务回执示例可由提交响应或后续状态查询取得。

```json
{
  "award_id": "W8",
  "order_id": "O8",
  "credit_reserved_minor": 90000
}
```

授信仅剩 80000 分时返回 409，列出缺口 10000 分，已批准的报价可改为减少数量后重新审批。

## 升级、部署与恢复

旧零售单按原订单号提供售后。只对主动签约的企业开通账期，初始授信为零。 在隔离副本运行迁移预检，输出记录数量、归属冲突和待处理编号。新增结构先部署，回填分批提交并保存游标，完成对账后按租户启用新入口。

演练时在首次成功写入新业务后中断进程，从检查点重启。核对授信日记账序号和原订单退款回执。需要退出试点时停收新请求，排空已受理操作并导出未决清单。涉及数据恢复时同时恢复数据库与关联证据，再核对外部已生效的动作。

### A13 计价口径

本例不含运费或其他折扣，每件 9 元。退货按原收货批次计价。必须能分别下载收货单、原账单及贷项行，并通过同一采购行号关联。

## 分期交付

1. **协议及授信。** 交付可导入的样例和可读回的第一批业务对象，验证基础身份、归属及版本。
2. **询价至多店履约。** 串通参与角色和执行入口，演练并发、重复请求及部分成功后的恢复。
3. **月结与红冲。** 完成全流程验收、容量实测和旧版升级。随开源发行提供中文配置、样例输入输出、备份恢复步骤及已知限制。
