# 多商户全渠道电商系统｜MySQL 数据与集成

## 持久化边界

MySQL 8.4 InnoDB 是本项目业务状态与授权关系的权威存储。租户身份进入业务唯一键与关联检查。媒体、文件、备份或模型大对象允许使用文件或对象存储，库内保存版本化引用、长度、摘要及所有者。派生缓存可从持久记录重新构建。

## 逻辑实体与事实来源

| 业务域 | 核心实体与必要字段 | 写入时必须维持的规则 |
|---|---|---|
| 商家与经营主体 | merchant(id,mode,payee,status), shop_member(shop,user,role) | 审核锁定收款主体及结算协议，停业仅阻断新交易，历史售后仍分派至原商户。 |
| 商品与搜索 | sku(shop,code,spec), listing(sku,channel,rev) | 售价、属性和可售渠道按发布版生效，索引滞后时结算重新校验。 |
| 会员与营销 | promotion(id,rev,scope), coupon_claim(member,coupon), allocation(line,rule,minor) | 按活动版本校验叠加顺序，折扣按合格行金额分摊到最小币种单位，尾差分配给固定排序的最后一行。 |
| 购物与订货 | cart_line(member,sku), quote(id,expires,rev), order_line(order,sku,paid) | 选中行按商家、仓及提货方式分组，库存和促销重算后需要买家确认有变化的报价。 |
| 库存与预售 | stock(warehouse,sku,available), hold(order,line,expires), preorder(sku,quota) | 可用量扣除已占数量，关单与支付回执争用同一状态；逾期实收进入退款或人工查单。 |
| 支付与拆单 | payment(order,channel_ref,minor), seller_order(parent,shop,state) | 冻结父子订单关系，渠道回执核对币种、金额与支付身份，部分失败不重复创建子单。 |
| 履约与自提 | shipment(suborder,warehouse,tracking), pickup(order,store,used_at) | 按已支付数量分配，部分发货可继续履约；自提码绑定订单和门店，签收事件带外部流水号。 |
| 售后与结算 | return_line(line,qty,minor), settlement(shop,period), posting(source,fee,net) | 退款以原行实付为上限，退货验收后追加负向结算行；打款和财务复核分权。 |

## 事务、索引与对账

- **身份与约束**　支付流水按渠道与流水号唯一，退款按原支付及申请键唯一，结算行按源事件及商户唯一。
- **业务索引**　店铺＋业务日＋结算状态定位应结账单，订单号＋包裹号定位部分履约。
- **数据生命周期**　财务审计保留金额与凭证；收货地址按履约权限展示，导出按商家脱敏。

预占库存与订单写入同一事务，退款锁原支付行核对剩余可退额。收款回执按渠道流水去重，结算按商户、币种、关期查询。

列表使用租户、业务状态、更新时间和稳定主键分页。外部事件保留来源、外部号、内容摘要、处理结果和业务对象引用。同键不同内容产生显式冲突；网络超时后按原键查单。跨存储发布应先确认文件持久，再发布其数据库引用；回收须验证没有有效引用。

## 集成契约

模拟支付、承运商与本地账单导入；商户上传回执必须标出原单号、币种、金额和外部号。

下单提交报价版、收货方式与幂等键；输出父单、子单及支付意图，价格变动返回重新确认项。

结算预览按商家、结算周期及币种列出销售、佣金、退款、待结净额，确认后冻结明细。
