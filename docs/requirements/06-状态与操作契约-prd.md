# 多商户全渠道电商系统｜状态与操作契约

## 交易与退款的生命周期

待付款→已付→部分履约→完成；未付款到期可关闭。退款按申请、验货、认可、原路退回、渠道确认独立流转。

## 权限与操作者

运营审核店铺，商家维护本店商品与履约，消费者管理本人订单，门店只核销本店自提，财务复核结算。 在待审批与已完成状态分别检查读写范围，委托与代办保留真实操作者身份。

## 两个关键交互

1. 下单提交报价版、收货方式与幂等键；输出父单、子单及支付意图，价格变动返回重新确认项。
2. 结算预览按商家、结算周期及币种列出销售、佣金、退款、待结净额，确认后冻结明细。

## 业务操作与异常回执

| 操作域 | 在当前数据上的处理 | 冲突、拒绝或降级行为 |
|---|---|---|
| 商家与经营主体 | 审核锁定收款主体及结算协议，停业仅阻断新交易，历史售后仍分派至原商户。 | 甲停业后原单仍可退货。 |
| 商品与搜索 | 售价、属性和可售渠道按发布版生效，索引滞后时结算重新校验。 | 旧搜索命中下架款，提交时明确拒单。 |
| 会员与营销 | 按活动版本校验叠加顺序，折扣按合格行金额分摊到最小币种单位，尾差分配给固定排序的最后一行。 | 第二次领同一单次券时返回已领取。 |
| 购物与订货 | 选中行按商家、仓及提货方式分组，库存和促销重算后需要买家确认有变化的报价。 | 报价过期不能使用旧折扣扣款。 |
| 库存与预售 | 可用量扣除已占数量，关单与支付回执争用同一状态；逾期实收进入退款或人工查单。 | 迟到支付不能复活已转售商品。 |
| 支付与拆单 | 冻结父子订单关系，渠道回执核对币种、金额与支付身份，部分失败不重复创建子单。 | 同流水重复回调三次仅确认一次。 |
| 履约与自提 | 按已支付数量分配，部分发货可继续履约；自提码绑定订单和门店，签收事件带外部流水号。 | 两次扫码核销只计一次提货。 |
| 售后与结算 | 退款以原行实付为上限，退货验收后追加负向结算行；打款和财务复核分权。 | 已结月份收到退款，原报表保持可追溯并在下期冲回。 |

## 失联、中断及恢复

预占库存与订单写入同一事务，退款锁原支付行核对剩余可退额。收款回执按渠道流水去重，结算按商户、币种、关期查询。 中断后先查询最后一个已持久的业务标记，再决定安全重试、补偿或人工复核。对外回执携带对象身份及业务版本。批量操作允许逐项查看成功、失败和未开始。

## 发布级业务断言

额外退运费由售后决定单明确承担方；券与积分恢复策略绑定原活动版本。 收取 180，子单 108 和 72；A 全退后退款 108，B 商家净应结 64.80，A 的佣金同步冲回。
