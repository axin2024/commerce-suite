# 跨店优惠规则

平台运营在「会员与营销」发布活动，可指定分类、结束时间、自动使用或先领券使用。门槛只计算资格商品，且这些商品须来自至少两家店铺。允许叠加会员价时，以会员价计算资格金额。其他活动的资格行按标价计算。

| 优惠方式 | 示例 |
| --- | --- |
| 固定满减 | 满 ¥200.00 减 ¥20.00。比例留空 |
| 按比例优惠 | 满 ¥200.00 按 12.5% 减免，最高减 ¥30.00 |
| 阶梯扩展 | 每满 ¥100.00 减该档金额的 12.5%，最高减 ¥22.00 |

比例和阶梯金额先向下取整至分，再按资格行金额分摊。分摊的尾差从最大商品 ID 的行开始补齐，每行优惠不超过商品行金额。优惠后的本店商品金额用于判断包邮，再处理积分抵扣。自动活动比较商品净额，主动选券时只用所选券。

活动新版生效后，新领券按新版计算；已领券记住原版。确认订单时重新检查活动版本、适用商品和每行金额。成交记录保存活动版本及行级优惠。退款按原行金额作冲正，即使活动已修改或停用。全单退完且原版允许退券时，未过期券按原条款返还。

## 安装阶梯示例

将 `COMMERCE_PROMOTION_EXTENSION` 设为应用可读取、位于 Web 根目录之外的 PHP 文件绝对路径。Compose 示例路径是 `/app/examples/promotion-steps.php`。启用后，发布活动时可选「按满额档位累计优惠」。

[示例文件](../examples/promotion-steps.php)返回以策略编号为键的数组。每项包含 `label`、表示是否接受比例参数的 `uses_rate`，以及用来计算整单优惠的 `discount` 闭包。

| 扩展契约 | 约束 |
| --- | --- |
| 输入 | 资格商品金额、门槛、优惠上限均为整数分。比例以基点表示，1250 代表 12.5%。无比例时为 `null` |
| 输出 | 0 至优惠上限和资格金额中的较小值，必须是整数分。返回 0 表示本单无可用优惠 |
| 权限 | 部署者加载受信 PHP 文件，平台运营从已注册策略中选用并发布。闭包只做纯计算 |
| 版本与重试 | 同一策略编号的计算语义保持稳定。变更计算语义时用新编号。报价和下单可重复调用 |
| 取消与退款 | 已持有优惠券随未付款订单关闭释放。退款使用订单原始行金额和活动版本 |
| 失败 | 已达到门槛的规则无法加载或返回越界金额时，本次报价或下单失败。其他商户库存、优惠券和账务保留原状态 |

要替换扩展时，可以先发布新编号，并保留旧策略到已领券过期。若需提前停止使用，应先停用相关活动。删除扩展前，可在仅配置内置规则的测试环境回放历史订单及退款。

## 回放样例

| 场景 | 输入 | 预期结果 |
| --- | --- | --- |
| 通过 | 两家店分别为 ¥120.00 和 ¥80.00，阶梯门槛 ¥100.00，每档 12.5%，上限 ¥22.00 | 两档计算得 ¥25.00，封顶后减 ¥22.00，商品合计应付 ¥178.00 |
| 拒绝 | 保留该报价，运营发布同金额的新版本，再提交旧报价 | 提示重新报价，旧报价不生成订单 |
| 拒绝 | 自定义闭包返回超过上限 1 分 | 拒绝该次报价 |

`php tests/integration.php` 验证分摊尾差、领券版本、原单退款和越界策略。示例扩展启用时，`tests/web_smoke.py` 从运营发布验到买家结账与旧报价被拒绝。
