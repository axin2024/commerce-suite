# 店铺运费规则

审核通过后，店主可从「商家中心 → 运费规则」发布新版本。按仓计费乘以实际参与发货的仓数，按单计费在每张商家子单收取一次。跨店结账分别计算各店运费，再加总到母订单。没有发布版本的店铺按 ¥8.00 每仓计算。

包邮门槛可留空。启用时，以本店商品使用会员价和活动优惠之后、抵扣积分之前的金额判断。达到门槛即免该店运费。门店自提免运费。

发布表单携带当前版本号。另一位操作者已更新规则时，旧表单会收到刷新提示。下单重新读取计费版本及分仓结果，若与报价不一致则提示买家重新报价。创建订单后，运费与版本写入本店子订单，可从「店铺订单」查看。售后退款继续按子单原运费核对可退上限。

## 安装计费扩展

应用启动配置可指定一个受信任的 PHP 文件。文件由部署者维护，应放在 Web 根目录外。原生部署设置 `COMMERCE_FREIGHT_EXTENSION` 为绝对路径。Compose 示例可在 `.env` 设置 `COMMERCE_FREIGHT_EXTENSION=/app/examples/freight-consolidation.php`，然后重新创建应用容器。

[首仓原价、其余仓半价](../examples/freight-consolidation.php)示例注册了 `consolidation_v1`。配置生效后，它会出现在店主的运费规则表单中。文件返回以策略编号为键的数组，每项提供中文或英文 `label` 和 `charge` 闭包。

| 契约项 | 格式 |
| --- | --- |
| 策略版本 | 编号带版本后缀，如 `consolidation_v1`。计费语义改变时使用新编号 |
| 输入 | 基础运费整数分，实际发货的仓库 ID 到件数的映射，按仓库 ID 升序传入 |
| 输出 | 总运费整数分，范围为 0 至 3,000,000,000 |
| 执行 | 报价与确认订单都可多次调用。相同输入应返回相同结果，闭包只负责纯计算 |
| 发布权限 | 仅当前店铺店主通过版本校验后发布，应用侧校验策略已注册 |
| 异常 | 无法使用策略时整次报价或下单失败。未确认的预占与订单写入随事务回滚 |
| 取消与重放 | 已下单的订单按原金额取消、履约和退款。已成交报价重放返回原订单 |

在移除扩展前，先将使用它的店铺发布到仍可用的策略，再移除配置。旧子单继续保留成交运费和版本。

## 示例验收

将一件 SKU 分配到两个仓，主仓库存 1 件，另一个仓至少 1 件。选择示例策略，基础运费填 ¥7.01，包邮门槛留空。

| 场景 | 输入 | 预期结果 |
| --- | --- | --- |
| 通过 | 同店购买 2 件，两个仓各发 1 件 | 首仓 701 分，另一个仓 350 分，共 1051 分。子单记录该策略版本 |
| 拒绝 | 买家保留该报价，店主发布新版本后再用旧报价下单 | 页面提示重新报价，旧报价不会生成订单或占用库存 |

`tests/integration.php` 回放两仓计费、规则冲突、包邮门槛、已下单运费冻结和扩展撤换。使用示例扩展启动演示服务后，`tests/web_smoke.py` 也会下单验证，并从商家订单查回成交规则。
