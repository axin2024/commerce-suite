# 架构与业务规则

## 模块

- `public/index.php` 处理会话、角色页面、表单校验及跳转。购物车行随买家账号保存在 MySQL，PHP 会话保存当前页面展示的报价。
- `src/Commerce.php` 执行交易与支付规则。写入方身份和归属在服务层复查，页面按账号或店铺过滤。
- `src/CatalogOperations.php` 处理商品系列、SKU 与发布审核。每次审批形成可查的版本，审核期间继续使用上一在售版。
- `src/PromotionOperations.php` 处理会员等级、活动发布、领券和计价。券绑定领取时的活动版，活动当前版供新领券或自动匹配使用。
- `src/InventoryOperations.php` 分配发货仓、保存订单行配额，按仓处理预留、释放及扣减。
- `src/ShippingOperations.php` 登记仓内包裹，以签收事件推进子订单状态。
- `src/PickupOperations.php` 管理自提门店与库存仓，处理备货、买家领码及门店核销。
- `src/PreorderOperations.php` 管理 SKU 的预售额度、截单时间、到货和库存转换。
- `src/ReturnOperations.php` 跟踪退货申请、寄回、验收和渠道退款，按原订单行分摊退款与佣金冲正。
- `src/SettlementOperations.php` 按店、币种和月份预览结算，冻结分录并管理复核、流水登记及导出。
- `src/ChannelBillOperations.php` 校验上传的渠道账单，按记录排队并与本地回执核对。
- `database/schema.sql` 保存初版基线，`database/migrations/` 按编号增量升级。迁移以数据库为范围加锁，成功后记录版本。MySQL 的 DDL 会隐式提交，迁移步骤需要能中断后续跑。
- `bin/commerce.php` 提供迁移、演示种子、运营账号配置、超时订单释放和渠道账单核对。应用连接统一使用 UTC，金额按人民币分保存。

## 交易状态

| 对象 | 路径 | 约束 |
| --- | --- | --- |
| 店铺 | 待审核 → 激活 / 拒绝，激活 ↔ 暂停 | 运营审核时留存收款主体和协议版本。暂停期间保留历史履约、售后和结算 |
| SKU 发布版 | 待审核 → 通过 / 拒绝 / 撤回 | 同系列在售规格唯一。下架立即生效，待审版本随下架撤回 |
| 报价 | 有效 → 已使用 / 过期 | 十分钟有效。确认时核对商品和价格快照 |
| 母订单 | 待付款 → 已付款 / 已取消 | 下单时锁定库存，十五分钟支付期限 |
| 预售批次 | 接单中 → 已截单 → 已入库 | 到截单时间自动停止新订单，商家可提前截单或到货入库。原有订单仍可在支付期限内付款 |
| 配送子订单 | 待付款 → 待履约 → 部分发货 → 待签收 → 已履约 | 全量一次发货时直接进入待签收。全部包裹签收后记账 |
| 自提子订单 | 待付款 → 待备货 → 待提货 → 已履约 | 付款扣减下单所选门店的库存，备货后开放提货码，核销后记账 |
| 退货退款 | 待审核 → 待寄回 → 待验收 → 待渠道退款 → 已退款 | 审核或验收可以拒绝。验收可通过部分件数，并单独记录回库件数 |
| 分录 | 待结算 → 已入批次 | 店铺维度串行记账和结算，已入批次的分录继续留存 |
| 结算单 | 待复核 → 待打款 → 已登记打款 | 复核后应结为零时直接结清。冻结时保存收款主体、协议及净额 |

## 一致性

- 报价令牌绑定买家。下单锁定报价、按店铺和 SKU 编号顺序加锁，比较交易快照，再统一写入母单、子单、库存预留和快照商品行。重复提交返回已关联订单。
- 购物车修改与结账按买家账号串行处理。报价记录所选商品行的版本，下单时再次比对，并在同一事务中清除已结账的行。未勾选的行保留。
- 店主可开设或停用本店岗位账号。服务端在商品、履约、售后及查账入口分别核对岗位和店铺编号，关键写入同时锁定成员授权，审计记录保存实际操作账号。
- 付款与取消锁定同一母单，再按 SKU ID 更新库存。流水按支付来源去重，每笔母单只有一笔确认收款。迟到实收进入退款队列，未执行的超时关单在同一事务内完成。
- 配送优先使用默认仓库存，再按仓库编号顺序分配。下单复核报价中的分仓明细，任一商品配额变化需重新确认报价。同一 SKU 的总库存、预留量等于各仓余额之和。配送每个发货仓收取 ¥8，分成多个包裹时沿用报价运费。
- 包裹只能发送该子订单分配到本仓的待发数量。登记时按店铺和子订单加锁，提交键和内容摘要共同约束重试。运单按承运商和运单号唯一，签收事件按承运商和事件流水唯一。
- 每个自提门店绑定本店一个库存仓。跨店自行选择各子订单的提货门店，每笔订单保存门店地址快照。停接新单后，已有子订单仍可备货与核销。
- 发布表单和库存表单分别携带版本。审核只切换在售版，库存预留、扣减或释放只提升库存版本。报价核对在售版及渠道，订单行保留成交版以查询当时的价格和规格。
- 资格商品须覆盖至少两店。叠加会员价的活动以会员实售价计算门槛，其他活动以资格行标价计算。自动活动比较最终实付，使用一项价格最优的活动。主动选券只计该券。
- 按资格行金额比例分配跨店优惠，尾差从 SKU ID 最大的资格行开始补分，上限为各行原金额。订单记录活动版本、标价、成交单价及优惠分摊。
- 同一会员对同一活动只可领一张券。创建待支付订单时预占，关单释放，付款核销。领券活动可在发布版开启全单退完返券。退款确认按母订单加锁，所有商品行的确认退款数量达到购买数量后，原版未到期的券解除当前核销，并按母订单保存返券记录。新版开关不改变旧单规则，历史发行版默认保留核销。零元优惠订单在本地完成结算并扣库。
- 履约时生成销售分录，包含商品实收及运费。佣金按优惠后的商品金额计提。验收时按订单行累计接受的退货数量计算本次货款及佣金冲正，并锁定金额。等候渠道确认的数量也占用可退上限，多次部分退款可以乱序入账，全部商品退款合计等于商品行实付。
- 售后客服审核并保存退货地址，买家登记退回运单，履约岗位验收。仅可售件数回补退货仓和 SKU 总库存。商家客服和平台财务可在审核通过后、验收前登记各自承担的原配送费退款。审批中的决定与已退款金额共同占用同一子订单的运费上限。撤回决定或验收拒绝后释放额度，验收通过时冻结货款与运费合计。
- 渠道确认全额后追加退款分录，原销售及已结算批次保留。应结净额按总额减佣金加平台承担运费计算，商家承担的运费计入本店退款支出。升级前的售后和分录在新运费字段中使用零值。
- 负余额继续结转。冻结汇总该店同币种、截止日期前尚未入批次的分录。履约、退款入账和结算共同按店铺行加锁。
- 数据库发生死锁或锁等待超时后，应用最多尝试三次。业务校验失败立即回滚。

## 预售库存

批次可售额度等于总额度减待付款预占和已付款数量。订单快照保存批次、库存仓及预计到货日。批次预占和母单创建在同一事务内，支付与关单先锁母单，再按 SKU 顺序处理库存与批次。到货流程按店铺、SKU、批次加锁。批次接单状态改变后，旧报价在下单时重新校验。

整批收到时，实收必须覆盖所有已付款和待付款预占。已付款明细直接生成可发货配额。待付款数量进入实物仓的预留量，后续随付款扣减，随关单释放。剩余实收转为现货。重复登记同批同数量返回原结果。配送单等待所有预售明细可发且包裹签收后入账，门店在预售明细全部到货后可备货。

## 提货码

买家只能为本人已备货的子订单生成提货码。页面显示 16 位随机码及条码，刷新后可重新生成。数据库保存摘要和 48 小时有效期，新码替换旧码。条码使用 [Code 39](https://www.iso.org/standard/77799.html)。

门店账号只能处理所属提货门店的子订单，店主可处理本商户的各个门店。核销在同一事务内写入操作人、子订单状态及销售分录。重复扫描同一个已核销码返回已核销状态，保留首次操作记录。

## 结算与打款登记

- 财务选择店铺和结算月份，预览人民币销售、退款、净佣金及应结净额。月份截止于次月首日零点 UTC。预览提交时核对分录和收款资料快照。重复确认同一快照返回同一单号。
- 冻结后，结算月份不得重开或倒签。已入账的退款如果晚于原销售关期，会留在未入批次分录中，进入之后的结算单。净额为负时暂缓冻结，待后续销售抵扣。
- 财务复核金额。出纳只处理已复核且应付为正的单据，录入已完成转账的银行流水及实付金额。流水号唯一，重复登记保留首次记录。审计保存冻结人、复核人和出纳账号。
- 商户店主和店铺财务可查看、导出本店冻结分录。CSV 包含源事件、子订单编号、业务时间和整数分金额。旧结算批次保留明细，历史月份和付款信息以原始记录为准。

## 渠道账单核对

CSV 使用 UTF-8，最多 256 KiB 和 1,000 条数据记录。第一行固定为 `kind,order_id,reference,currency,amount_minor`，其中订单号是母单 ID，金额是整数分。每一行是一条记录。

| 类型 | 核对来源 | 流水字段 |
| --- | --- | --- |
| `capture` | 已保存的沙箱收款回执 | 原收款流水 |
| `return_refund` | 已确认的退货退款回执 | 渠道退款流水 |
| `exception_refund` | 已登记退款的异常实收回执 | 异常实收的退款流水 |

- 上传以操作账号和文件摘要识别重试。完全相同的行保留首条用于匹配，其余标记重复。同一类型和流水出现冲突字段时，全组标记冲突。
- 每次后台执行领取最多 100 条待核对记录。支持多个进程，事务提交前中断时由下一次执行接手。匹配按类型、流水、母单、币种和金额核对，保留记录序号、结果、检查时间和关联回执。
- 商户上传的证据先检查本店子单归属。商户可查看本店任务和自填数据，平台财务可查看跨店母单的比对结果和本地回执。待补回执由平台财务重新排队，原任务编号继续有效。

## 部署范围

示例启动方式只监听本机。对外部署需配置 HTTPS、`COMMERCE_SECURE_COOKIES=1`、反向代理层的登录与注册限流、库备份和定时任务。请使用自有运营账号并保持演示模式关闭。真实渠道接入涉及支付回调验签、退款回执和异步对账。

## 沙箱支付回执

`POST /payment-webhook.php` 接收 JSON 请求，正文最多 8192 字节。字段为 `payment_token`（订单页显示的 32 位十六进制支付意图）、`reference`（渠道流水）、`amount`（整数最小货币单位）和 `currency`（三位大写币种编码）。订单币种为 CNY。

- `X-Commerce-Timestamp` 为 Unix 秒，时钟允许前后偏差 300 秒。
- `X-Commerce-Signature` 为小写十六进制 HMAC-SHA256。以 `COMMERCE_SANDBOX_WEBHOOK_SECRET` 为密钥，签名内容为时间戳原文、一个英文句点、未经重新序列化的请求正文。
- 业务受理返回 HTTP 200 和 `receipt_id`、`status`、`payment_id`。状态为 `accepted`、`needs_review`、`refund_required` 或 `refunded`。未入账时 `payment_id` 为 null。
- 同一流水重试应使用原正文。可更新签名时间。正文冲突返回 HTTP 409，验签失败返回 HTTP 401，暂时无法提交返回 HTTP 503。
- 财务用退款回执号登记异常实收的沙箱退回。此记录只更新对应异常回执。原订单状态、库存及已确认收款均保留。

## 沙箱签收回执

`POST /shipping-webhook.php` 需要 `APP_DEMO=1` 和至少 32 字节的 `COMMERCE_SANDBOX_SHIPPING_SECRET`。签名和时间窗与支付回执一致，使用签收专用密钥。JSON 字段包括 `carrier`（小写承运商代码）、`tracking`（已登记运单号）及 `event_reference`（承运商签收事件流水）。

- 成功返回 HTTP 200 和 `event_id`、`shipment_id`、`status`，其中状态为 `delivered`。用同一运单和事件流水重试返回原事件编号。
- 运单不存在或流水已绑定其他运单时返回 409。验签失败返回 401，请求字段无效返回 422，暂时无法提交返回 503。
- 同一运单收到多个有效的签收事件时保留各流水，以首次签收时间更新包裹。只有最后一个包裹签收时完成配送子订单并生成销售分录。

## 沙箱退货退款回执

`POST /refund-webhook.php` 需要 `APP_DEMO=1` 和至少 32 字节的 `COMMERCE_SANDBOX_REFUND_SECRET`。使用退款专用密钥，签名格式和时间窗沿用支付回执。

| JSON 字段 | 内容 |
| --- | --- |
| `refund_token` | 验收通过后生成的 32 位十六进制退款意图 |
| `reference` | 渠道退款流水 |
| `payment_reference` | 对应母单的原支付流水 |
| `amount` | 与验收金额一致的整数分数值，允许为 0 |
| `currency` | `CNY` |

成功返回 HTTP 200 和 `refund_id`、`status: refunded`。用相同的字段重试会返回同一结果。金额、币种、原支付流水不匹配，或渠道流水已绑定其他申请时返回 409。验签失败返回 401，字段格式错误返回 422，暂时无法提交返回 503。
