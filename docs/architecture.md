# 架构与业务规则

## 模块

- `public/index.php` 处理会话、角色页面、表单校验及跳转。PHP 会话保存买家购物车和当前报价视图。
- `src/Commerce.php` 执行交易、库存、履约和财务规则。写入方身份和归属在服务层复查，页面按账号或店铺过滤。
- `database/schema.sql` 保存初版基线，`database/migrations/` 按编号增量升级。迁移以数据库为范围加锁，成功后记录版本。MySQL 的 DDL 会隐式提交，迁移步骤需要能中断后续跑。
- `bin/commerce.php` 提供迁移、演示种子、运营账号配置和超时订单释放。应用连接统一使用 UTC，金额按人民币分保存。

## 交易状态

| 对象 | 路径 | 约束 |
| --- | --- | --- |
| 店铺 | 待审核 → 激活 / 拒绝，激活 ↔ 暂停 | 运营审核时留存收款主体和协议版本。暂停期间保留历史履约、售后和结算 |
| 报价 | 有效 → 已使用 / 过期 | 十分钟有效。确认时核对商品和价格快照 |
| 母订单 | 待付款 → 已付款 / 已取消 | 下单时锁定库存，十五分钟支付期限 |
| 子订单 | 待付款 → 待履约 → 已履约 | 随母单支付解锁履约，取消时随母单关闭 |
| 退款 | 待审核 → 已审批 / 已拒绝 | 履约后允许按明细数量申请，待审数量计入可退量 |
| 分录 | 待结算 → 已入批次 | 店铺维度串行记账和结算，已入批次的分录继续留存 |

## 一致性

- 报价令牌绑定买家。下单锁定报价、按店铺和 SKU 编号顺序加锁，比较交易快照，再统一写入母单、子单、库存预留和快照商品行。重复提交返回已关联订单。
- 店主可开设或停用本店岗位账号。服务端在商品、履约、售后及查账入口分别核对岗位和店铺编号，关键写入同时锁定成员授权，审计记录保存实际操作账号。
- 付款与取消锁定同一母单，再按 SKU ID 更新库存。支付流水全局唯一，一笔母单只保留一条收款流水。过期订单拒绝收款，即使释放任务尚未执行。
- 商品编辑表单携带版本号。库存预留、扣减或释放会提升版本，防止未刷新的商家表单覆盖库存变更。
- 按商品金额比例分配跨店优惠。余数较大的商品行优先补分，同余数按商品 ID 升序处理。
- 履约时生成销售分录，包含商品实收及运费。佣金按优惠后的商品金额计提。退款按已退累计比例计算本次金额和佣金冲正，多次部分退款合计等于该行应退总额。运费保留，退款审批也不自动回补库存。
- 负余额进入下一批结算。结算记录只汇总该店尚未入批次的分录。履约、退款入账和结算共同按店铺行加锁。
- 数据库发生死锁或锁等待超时后，应用最多尝试三次。业务校验失败立即回滚。

## 部署范围

示例启动方式只监听本机。对外部署需配置 HTTPS、`COMMERCE_SECURE_COOKIES=1`、反向代理层的登录与注册限流、库备份和定时任务。请使用自有运营账号并保持演示模式关闭。真实渠道接入涉及支付回调验签、退款回执和异步对账。
