# 支付渠道接入

支付渠道由部署者注册。应用创建母单时固定渠道号、应付金额和支付意图，结账默认渠道切换只影响随后创建的订单。关闭演示模式后，正金额订单须配置收银渠道才能创建。历史演示订单沿用原回执路径。

## 注册渠道

将 `COMMERCE_PAYMENT_EXTENSION` 设为 Web 根目录外的受信任 PHP 文件绝对路径，并将 `COMMERCE_CHECKOUT_CHANNEL` 设为新订单使用的渠道编号。Compose 内置示例位于 `/app/examples/payment-bridge.php`。自定义文件可只读挂载进应用容器。

扩展文件返回以渠道编号为键的数组。一个编号对应一个收款账户与一套验证凭据。更换收款账户时应保留旧编号及其回执验证器，直到该渠道的未结交易和售后处理结束。

| 扩展接口 | 输入与结果 |
| --- | --- |
| `checkout` | 输入 `payment_token`、CNY 整数分 `amount`、`currency` 和 Unix 秒 `expires_at`，返回 HTTPS 收银台 URL。渠道用原意图查询或重试，同一意图应返回同一笔待付交易 |
| `verify` | 输入原始请求体和小写 HTTP 头，从原始内容验签后返回归一化事件。无关事件可返回 `null`。签名不符抛出 `InvalidPaymentSignature`，字段无效抛出 `UnexpectedValueException` |

买家仅可发起本人尚未过期的订单。发起收银台操作不扣库存、不标记成功。平台以已验签的实收回执确认支付、扣减预占和更新子单。

## 回执契约

渠道向 `POST /channel-webhook.php?provider=<渠道编号>` 提交原始回执，请求体上限 64 KiB。适配器验签并映射完成态事件后，交给业务事务处理。金额为整数分，币种为大写字母代码。流水可使用字母、数字、下划线和连字符，最多 80 字符。

| `type` | 额外字段 | 成功效果 |
| --- | --- | --- |
| `capture` | `token` 为支付意图 | 核对渠道、订单、币种和金额，扣库存并推进子单。迟到和重复实收登记待原路退回 |
| `return_refund` | `token` 为退款意图，`payment_reference` 为原收款流水 | 核对原渠道、原收款和售后金额，追加货款、佣金和适用的积分冲正 |
| `exception_refund` | `payment_reference` 为待退回的实收流水 | 核对同渠道原流水和全额退回金额，关闭待处理回执 |

三类事件均包含 `reference`、`amount` 和 `currency`。财务可在平台操作台查到待退款意图和原交易流水，再通过渠道发起实际退款。外部渠道的退款成功后投递回执。现金退款金额为零的退货由财务在平台内确认，完成对应的商品、积分和优惠券处理。

相同渠道和流水重投返回原处理结果。归一化事件内容变化返回 HTTP 409。签名错误返回 401，字段错误返回 422，暂时处理失败返回 503。渠道收到 503 可按原流水重投。字段、金额和渠道差异应保留原事件供财务核对。订单取消及过期会释放预占，之后到达的实收进入待退回队列。

财务可将原五列账单模板扩为 `kind,order_id,reference,currency,amount_minor,provider`。最后一列填渠道编号，五列旧模板沿用 `sandbox`。账单只核对已持久化的回执。

## 桥接示例

[桥接扩展](../examples/payment-bridge.php)注册 `bridge_v1`，读取 `COMMERCE_BRIDGE_CHECKOUT_URL` 与两把独立的签名密钥。收银桥按原查询串验证 `COMMERCE_BRIDGE_CHECKOUT_SECRET` 的 HMAC-SHA256 十六进制签名，核对过期时间并以支付意图去重。回执请求携带 `X-Bridge-Timestamp` 和 `X-Bridge-Signature`，使用 `COMMERCE_BRIDGE_WEBHOOK_SECRET` 签名，签名输入是 Unix 秒、一个点和未经改写的请求体。允许时差 300 秒。

| 回放 | 条件 | 结果 |
| --- | --- | --- |
| 通过 | 收银意图应付 ¥120，签名有效，实收 12000 分。原事件重投两次 | 同一笔收款、同一条回执。子单进入待履约 |
| 拒绝 | 相同意图实收 12001 分，或在已有流水下改金额重投 | 前者登记待核对，订单保持待付款。后者返回 409 |

使用演示种子初始化独立测试库后，以 `APP_DEMO=0` 启动配置了样例的本机服务。测试进程使用同一组示例环境变量，运行 `python3 tests/payment_channel_web.py`。回归验证签名的收银链接、实收入账、退货退款、迟到实收退回和渠道对账，不访问外部支付服务。
