# 业务验收

2026-11-24 以 `85c40ff` 的应用代码验收。PHP 8.2.30 和 Python 3.14 在 Windows 本机运行，分别使用 MySQL 8.0.46 和 8.4.13 的独立数据库。空库健康检查返回 HTTP 503，迁移后返回 200，重复执行迁移显示 `Schema is current`。两种 MySQL 各通过 488 项数据库集成检查和 15 组网页流程。网页流程使用 HTTP 请求和独立角色会话，覆盖页面表单、CSV 和签名回执。

## 跨店交易样例

买家选中 A 店 ¥120 和 B 店 ¥80 的商品，使用满 ¥200 减 ¥20 的券，两店均到店自提、佣金率 10%。以下为本次 MySQL 8.4 网页回归的首单回读。单号为合成环境内的编号。

| 对象 | 库内结果 |
| --- | --- |
| 母单 #1 | 商品合计 ¥200，减 ¥20，实付 ¥180。有效支付 1 条，已入账的渠道回执 1 条 |
| A 店子单 #1 | 原价 ¥120，分摊 ¥12，实付 ¥108。退款 ¥108，佣金 ¥10.80 全额冲回。结算单 #2 净额 ¥0，零额结清 |
| B 店子单 #2 | 原价 ¥80，分摊 ¥8，实付 ¥72。结算单 #1 净额 ¥64.80，已登记打款。CSV 可按子单编号查到原分录 |

沙箱发送第一条回执后在读取响应前断开连接。财务页先查到该流水已入账，再用原渠道流水重试两次。两次响应的支付编号与回执编号一致。双方分别用店主账号尝试按对方店铺查询、读取对方结算详情和下载其 CSV，六个请求均返回 HTTP 403，各自列表只含本店结算单。

## 备份恢复与旧版升级

用 `v0.1.0` 的源码与集成测试在 MySQL 8.0.46 生成待付、已取消、已成交、已退款及已结算的历史记录。通过 `mysqldump --single-transaction --no-tablespaces --set-gtid-purged=OFF` 导出，恢复到空的 MySQL 8.4.13 数据库，再执行本版的全部 20 个迁移。第二次迁移显示 `Schema is current`，应用健康检查通过。

按主键比对 3 张母单、4 张子单、4 条订单行、1 笔支付、1 张退款单、3 条财务分录和 2 张结算单。订单状态、金额、原流水与账务归属一致。4 张子单的回填下单时间逐条等于母单时间。两张历史结算单仍可区分，净额分别为 ¥0 与 ¥64.80。恢复命令见[部署与恢复](deployment.md#备份与隔离恢复)。

## 复现和范围

- 依照 [README](../README.md#本机运行)在独立且名称以 `_test` 结尾的空库执行迁移。运行 `php tests/integration.php` 前设置 `APP_DEMO=1`。并发用例需要 CLI `proc_open`。
- 在另一个空库迁移并导入种子。为 Web 与测试进程设置相同的支付、签收和退款沙箱密钥。可同时配置[运费](freight.md)与[营销](promotions.md)的示例扩展。启动应用后运行 `python tests/web_smoke.py http://127.0.0.1:8080`。
- 关闭演示模式后的[支付桥接验收](payment-channels.md)使用本机签名夹具核对收银请求、实收、退款、迟到支付与渠道对账，真实渠道的资金流水需在其环境另验。
- [承运商接入](carrier-adapters.md)追加验收覆盖迁移 `0021`。MySQL 8.0.46 和 8.4.13 各通过 497 项集成检查，旧沙箱运单的事件编号、状态和账务在升级和重放后保持一致。关闭演示模式后回放外部支付与承运商事件。8.4 测试子单有两件包裹、八条有效轨迹记录，最终只入一笔 ¥248 的销售，含 ¥24 佣金。
- [外部渠道商品与库存](channel-catalog.md)验收覆盖迁移 `0022`。MySQL 8.0.46 和 8.4.13 均通过渠道 HTTP 回归。两家店使用同一渠道代码，各自只能读取被选入的 SKU。下单使演示商品的可售量由 36 降为 35，取消后恢复至 36。未审核改价保持原展示价格，通过审核后下一次读取显示新价格。两版数据库应用迁移后，已有订单、运单和账务记录的数量保持一致。
- [外部渠道订单](channel-orders.md)验收覆盖迁移 `0023`。两版 MySQL 分别用两个 PHP 进程提交相同订单，创建与重放返回同一单号。两个独立渠道可各自使用同一个外部单号。站内和外部渠道同时抢一件库存只有一笔有效预占，取消后库存回到 1。实际落库只有一笔 ¥129 收款和一笔签收后的销售分录，佣金 ¥12，应结 ¥117。既有渠道清单、订单和撤销状态在升级后保持一致。
- [外部渠道退货](channel-orders.md#退货与退款)验收覆盖迁移 `0024`。两版 MySQL 各通过 497 项集成检查和渠道 HTTP 回归。两个 PHP 进程同时登记同一笔退货，仅生成一张退货单。未签收、超量或跨店申请被拒绝。店铺停业后仍可审批、登记寄回运单和验收历史订单。签名回执重放仅入账一次，退款 ¥125（商品 ¥120、运费 ¥5），冲回佣金 ¥12，回库 1 件，原单销售和退款合计留存 ¥4 待结算。
- 库存争抢和订单查询的实测负载、耗时与原始样本见[容量验收](capacity.md)。本次部署和恢复使用本机 PHP 与 MySQL。容器启动单列在[持续集成工作流](../.github/workflows/test.yml)。承运商、银行与第三方渠道的接入现状见[支持范围](../SUPPORT.md)。
